# 1-я итерация: Interview Meta Agent

## Контекст

Хакатон 24 часа, трек «ПрокачAI PDLC». Разрабатываем систему, которая
на основании входных данных (интервью с пользователями) помогает
продуктовым менеджерам конфигурировать и описывать беклог.

**Первая задача:** разработать агента, который на основании текстов
пользовательских интервью генерирует структурированную метаинформацию.
Метаинформация в будущем позволит другим агентам приоритизировать боли
и понимать, насколько та или иная проблема реальна.

## Принципы

1. **Цитата обязательна** — каждый вывод подкреплён прямой цитатой
   из текста. Нет цитаты → нет вывода. Защита от галлюцинаций.
2. **Факт ≠ интерпретация** — «пользователь сказал X» (факт) и
   «агент оценил это как trust_breach с intensity 2» (интерпретация) —
   разные поля. Факты неизменны, интерпретации — гипотезы.
3. **Пустое лучше выдуманного** — если информации в тексте нет,
   поле остаётся пустым. Не додумывать.
4. **Комментарии = гипотезы, не вердикты** — каждый комментарий
   формулируется как наблюдение («судя по тексту...», «возможно...»).
   Агент не знает продукт, его ЦА и стратегию — финальную оценку
   делают другие агенты.
5. **Сегмент — по маркерам** — ИП/бизнес/физлицо определяется по
   косвенным маркерам из текста, не гадать.
6. **Канал абстрагирован** — `source` универсальный: не привязан
   к файлам, Jira, чату или чему-то ещё.

## Схема метаинформации

Все поля опциональны, кроме `meta_id`, `source`, `pains.title`, `pains.quote`.

### meta_id (required)
Уникальный ID. Детерминированный: SHA256(файл)[:8] → `META-abc12345`.
Повторный прогон того же файла = тот же ID → идемпотентность.

### segment
Тип потребителя по маркерам из текста:
- `individual` — физлицо («зарплатная карта», «коллега на работе»)
- `sole_proprietor` — ИП («в моём ИП»)
- `business` — бизнес («в моей компании», «корпоративная карта»)
- `unknown` — маркеров нет, поле пустое

С цитатой-маркером и confidence.

### source (required)
```
origin: "свободное описание"
modality: text | audio | video | structured
reference: "путь/URI/ID оригинала"
attributes: {}  # произвольные метаданные источника
```

### respondent
- `role` — только из текста
- `traits` — наблюдаемые черты
- `customer_status` — churned | churning | active | new
- с цитатой и confidence

### engagement
Оценивается по наблюдаемым сигналам:
- `usage_frequency` — daily | weekly | monthly | rare | unknown
- `product_knowledge` 0-3
- `usage_depth` 0-3
- `invested` — настроил под себя?
- `signals` — список фактов-доказательств
- `engagement_score` 0-10

### jobs (JTBD)
Формат: «Когда я [ситуация], я хочу [потребность], чтобы [результат]».

### competitors
- `name`, `relation` (came_from | uses_now | considered | returning_to)
- `likes`, `dislikes` — только из текста

### pains (ядро)
Каждая боль:
- `id` — `META-xxx-pN` (глобальный)
- `title` (required) — для матчинга похожих болей
- `quote` (required) — прямая цитата
- `description`, `context`, `related_jobs`
- **Сигналы реальности:**
  - `spontaneous` — сам заговорил vs ответ на вопрос
  - `past_behavior` — уже действовал для решения (главный фильтр)
  - `workaround` — обходное решение
  - `frequency` — daily | weekly | monthly | rare | unknown
  - `trust_breach` — подрывает доверие к данным/продукту
- **emotion:**
  - `valence` -2..+2
  - `intensity` 0..3
  - `markers` — frustration | resignation | enthusiasm | anxiety | sarcasm
- **commentary (гипотезы, не вердикты):**
  - `pain_nature` — defect | missing_feature | expectation_mismatch | ux_friction | trust_breach
  - `expectation_source`
  - `generalizability`
  - `alternative_explanations[]`
  - `caveats[]`

### support_experience
Эпизоды контактов с поддержкой (каждый: issue, outcome, quote)
и общая оценка: positive | neutral | negative.

### interview_commentary
Целостные наблюдения по интервью:
- `who_and_expectations`
- `expectations_vs_experience`
- `churn_driver_hypotheses[]`
- `audience_fit_signals`
- `evidence_quality`

## Архитектура

**Вариант B (выбран):** интеллект в SKILL.md, детерминированные операции
в коде.

```
1. convert_source(path) → текст + source    [CLI / MCP tool]
2. Host-агент (LLM) читает текст + SKILL.md
   → извлекает JSON с метой
3. validate_meta(json) → ошибки/ok          [CLI / MCP tool]
4. save_meta(json) → .md файл               [CLI / MCP tool]
```

### Структура проекта

```
interview-meta-agent/
├── SKILL.md              # инструкция для host-агента
├── cli.py                # CLI: convert | validate | save
├── mcp_server.py         # MCP-сервер (те же 3 tool-а)
├── core/
│   ├── schema.py         # Pydantic-контракт
│   ├── convert.py        # .txt → текст + source
│   └── renderer.py       # мета → .md (frontmatter + тело)
├── source/               # 6 интервью в .txt
├── examples/             # golden example
└── output/meta/          # результат
```

### MCP-сервер (3 tool-а)
- `convert_source(path)` — читает файл → текст + source
- `validate_meta(meta_json)` — валидация по схеме
- `save_meta(meta_json)` — рендер + сохранение в .md

### CLI (3 команды)
- `cli.py convert <path>` — прочитать файл
- `cli.py validate '<json>'` — валидировать
- `cli.py save '<json>'` — сохранить

## Результат проверки на INT-T-001

Проведён полный цикл (я = host-агент + CLI):
- Извлечено **6 болей** с цитатами
- 2 JTBD, 1 конкурент, 3 эпизода поддержки
- Комментарий: 3 гипотезы ухода, сигналы о ЦА, evidence quality
- Файл: `output/meta/META-6fdae63f.md` (225 строк)

### Ключевой инсайт по INT-T-001

4 из 6 болей содержат мотив «система молчит или вводит в заблуждение»
(trust_breach). Это сквозной паттерн, который будет виден при
агрегации по всем интервью.
