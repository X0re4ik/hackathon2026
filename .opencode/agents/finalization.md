# Финализация свода

Читается **один раз**, когда `sources[]` покрывает все меты входной папки. В цикле
итераций этот файл не читается — он существует отдельно, чтобы не тратить токены
на каждой итерации.

Здесь снимается правило 2: на финализации арифметика по всему файлу разрешена и нужна.
Читать файл свода целиком — тоже разрешено.

---

## Шаг 1: ревизия тем

Прочитай таблицу тем целиком. Найди:

- **пары тем с одинаковым смыслом под разными словами** — типичный результат того,
  что правило 3 велит при сомнении создавать новую тему;
- **темы с `overflow: true`** — их обязательно слить, флаг для этого и ставился.

Слияние: участники переезжают в одну секцию, теги объединяются, доли и сигналы
пересчитываются заново по объединённому составу, вторая секция удаляется вместе
со строкой в таблице. Формулировка обобщается по правилу 4.

ID слитой темы — меньший из двух. Освободившийся ID **не переиспользуется**: дырка
в нумерации честнее, чем ссылка, которая раньше значила другое.

## Шаг 2: ревизия формулировок

Каждая каноническая формулировка обязана покрывать всех своих участников. Не покрывает —
либо обобщи, либо раздели тему обратно.

Проверь дрейф: если формулировка темы обобщалась несколько раз, она могла превратиться
в бессмысленно широкую («хочу, чтобы банк работал хорошо»). Такую тему надо разделить.

## Шаг 3: свести словарь мотивов к 8

Теги C с `kind: мотив` — это язык описания сквозных проблем. Он работает, пока их мало.

Если мотивов больше восьми — слей близкие. Мотив, оставшийся на одной теме, скорее всего
не мотив, а домен: поменяй ему `kind` или влей в соседний.

Домены (`kind: домен`) не ограничиваются: их столько, сколько предметных областей
в продукте.

## Шаг 4: собрать раздел «Критичность»

### 4.1 Балл темы

Для каждой темы сложи веса сработавших флагов из строки `**Сигналы:**`:

| Флаг | Вес |
|---|---:|
| `churn-driver` | 3 |
| `trust-breach` | 1 |
| `hi-freq` | 1 |
| `no-workaround` | 1 |
| `multi-interview` | 1 |
| `multi-segment` | 1 |

Максимум 8. Балл темы с пустыми сигналами — 0, это законно.

### 4.2 Распределить балл по фасетам

Балл темы попадает в каждый фасет целиком и делится внутри фасета по долям из строки
`**Доли:**`.

Пример. Тема T-05, сигналы `churn-driver, trust-breach, multi-interview, multi-segment`
→ балл 3+1+1+1 = **6**. Доли `A/segment: business 67%, individual 33%`.

```
вклад в segment:business    = 6 × 0.67 = 4.02
вклад в segment:individual  = 6 × 0.33 = 1.98
```

Тот же балл 6 отдельно распределяется по `A/status`, по `B/nature`, по `B/freq`,
по `C/домен`, по `C/мотив`. Это не двойной счёт: фасеты — разные оси одного и того же
балла, а не слагаемые.

### 4.3 Сложить по тегам и нормировать

Для каждого тега: `вес = Σ по всем темам (балл темы × доля тега в теме)`.

Внутри каждого фасета переведи веса в проценты: `доля = вес / сумма весов фасета × 100`.
Проценты внутри фасета дают 100.

### 4.4 Написать раздел

```markdown
## Критичность

Не приоритет. Наблюдаемые сигналы, по которым приоритет расставит тот, кто знает
продукт, стратегию и трудоёмкость.

**Состав выборки: <N> интервью — <k> ушли, <m> уходят, <l> активны;
<по сегментам>.** Все доли ниже относятся к этой выборке, а не к базе пользователей.

### Баллы по темам

| Тема | Балл | Сигналы | Интервью |
|------|-----:|---------|----------|
| T-05 Экспорт операций | 6 | churn-driver, trust-breach, multi-interview, multi-segment | 3 |
| … сортировка по баллу вниз | | | |

### Где сосредоточена критичность

**A/segment**

| Тег | Вес | Доля |
|-----|----:|-----:|
| segment:business | 18.4 | 61% |
| segment:individual | 11.8 | 39% |

**A/status** — та же таблица
**B/nature** — та же таблица
**B/freq** — та же таблица
**C/домен** — та же таблица
**C/мотив** — та же таблица

### Как это считано

- балл темы = сумма весов флагов: `churn-driver` 3, остальные по 1, максимум 8;
- балл распределяется внутри каждого фасета по долям темы;
- доли `A/*` считаны по уникальным интервью, `B/*` — по привязанным болям
  (детерминированно, проверяется машинно); доли `C/*` — суждение агента;
- группа D в расчёте не участвует.

### Чего эти числа не говорят

- **не говорят о распространённости в базе:** выборка смещена — <k+m> из <N>
  респондентов уходят, поэтому «в 3 интервью из 6» ≠ «у половины пользователей»;
- **не содержат трудоёмкости** — из интервью она не выводится никак, а без неё
  приоритет не считается;
- **не содержат влияния на выручку** — для этого нужна стратегия, которой у агента нет;
- `evidence:past-behavior` и `evidence:spontaneous` в расчёт не входят: они `true`
  почти у всех болей и потому не различают темы. Живут в группе D.
```

Если тем с баллом 0 больше половины — скажи об этом прямо в наблюдениях: значит, флаги
на этих данных не работают и профиль критичности бесполезен.

## Шаг 5: собрать облако тегов

Четыре блока по группам, внутри каждого сортировка по весу вниз. Вес тега = **сколько
тем его несут** (не сколько интервью — интервью в отдельной колонке).

```markdown
## Облако тегов

Вес = число тем, несущих тег. Группа D в критичность не входит и приведена
как характеристика качества данных.

### Группа A — кто пользователь

| Тег | Вес | Фасет | Интервью | Пояснение |
|-----|----:|-------|----------|-----------|

### Группа B — что за проблема

| Тег | Вес | Фасет | Интервью | Пояснение |
|-----|----:|-------|----------|-----------|

### Группа C — тематика

| Тег | Вес | kind | Интервью | Пояснение |
|-----|----:|------|----------|-----------|

### Группа D — качество данных

| Тег | Вес | Интервью | Пояснение |
|-----|----:|----------|-----------|
```

Пояснение — определение из `tag_definitions`, дословно или сокращённо.

## Шаг 6: легенда

Раздел с расшифровкой групп, ставится **перед** облаком тегов:

```markdown
## Легенда групп тегов

| Группа | Отвечает на вопрос | Фасеты | В критичности |
|--------|-------------------|--------|:-------------:|
| **A** | кто пользователь | `A/segment`, `A/status` | да |
| **B** | что за проблема | `B/nature`, `B/freq` | да |
| **C** | о чём тема | `C/домен`, `C/мотив` | да |
| **D** | насколько верить данным | — | нет |

Внутри фасета проценты дают 100. `segment:business` и `status:churned` лежат в одной
группе A, но в разных фасетах: тема одновременно и про сегмент, и про статус, это
разные оси, а не альтернативы.

Вне фасетов: `engagement:*`, `trust-breach`, `evidence:workaround`, `support:failed` —
бинарные признаки, распределять их нечем.
```

## Шаг 7: наблюдения агента

2-5 наблюдений, сформулированных как гипотезы («судя по данным…»). Обязательно включи:

1. **Сквозные темы** — встречающиеся в разных сегментах. Самый ценный сигнал свода.
2. **Сознательные неслияния** — пары тем, похожих по словам, которые ты решил не сливать,
   и почему. Без этого следующий агент склеит их обратно.
3. **Качество данных** — что в выборке перекошено, каких данных не хватает, где
   сигнал слабый из-за объёма.

Наблюдение о том, чего в данных нет, ценнее наблюдения о том, что в них есть.

## Шаг 8: метрики

Строка сразу под заголовком `# Свод jobs`:

```markdown
**Интервью:** 6 | **jobs:** 22 | **тем:** 15 | **merge_rate:** 0.32
| **балл критичности:** макс 6, медиана 2
```

`merge_rate = 1 − темы / jobs`. Ноль означает, что не слилось ничего: либо интервью
не пересекаются, либо правило 3 применялось слишком строго.

# Чек-лист финализации

Структура и полнота:

- [ ] каждый мета-файл входной папки есть в `sources[]`;
- [ ] `meta_id` каждой меты встречается хотя бы раз — в секции темы или в «Болях вне jobs»;
- [ ] ни один job не размещён в двух темах;
- [ ] у каждой темы есть каноническая формулировка и хотя бы один участник;
- [ ] у каждого участника указаны `meta_id` и локальный `job id`;
- [ ] оригинальные формулировки участников сохранены дословно;
- [ ] `## Темы` идёт до первой секции темы;
- [ ] внутри frontmatter нет строк с `---`;
- [ ] тем не больше 30, тем с `overflow: true` не осталось;
- [ ] список интервью в заголовке совпадает с `sources[]`.

Теги:

- [ ] каждый тег из таблицы тем и секций есть в `tag_definitions`;
- [ ] у каждого тега есть `group`; у тегов A и B фасетных осей есть `facet`;
- [ ] у каждого тега группы C есть `definition` и `kind`;
- [ ] мотивов (`kind: мотив`) не больше 8;
- [ ] ни один тег не определён дважды;
- [ ] в `tag_definitions` нет тегов, которые нигде не используются — удали такие.

Доли и критичность:

- [ ] у каждой темы есть `**Доли:**` и `**Сигналы:**`;
- [ ] сумма процентов внутри каждого фасета — ровно 100;
- [ ] доли `A/segment` и `A/status` сходятся с составом участников темы;
- [ ] каждый флаг `churn-driver` подкреплён строкой `**Причина ухода:**` с `meta_id`
      и дословной цитатой;
- [ ] в долях и баллах не участвуют теги группы D;
- [ ] проценты внутри каждого фасета в разделе «Критичность» дают 100;
- [ ] блок «Чего эти числа не говорят» заполнен фактическим составом выборки,
      а не оставлен шаблоном.

Разделы:

- [ ] `## Критичность`, `## Легенда групп тегов`, `## Облако тегов`,
      `## Наблюдения агента` заполнены;
- [ ] облако тегов разбито на четыре блока по группам;
- [ ] строка метрик под заголовком заполнена.

Ошибки исправь и пройди чек-лист снова. Если есть `scripts/validate.py` — прогони его:
он пересчитывает доли и флаги из мет независимо и находит расхождения, которые глазами
не видны.
